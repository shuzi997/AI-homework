Agent 的使用过程

同一个工具，问法不同，产出差距可能是几倍。以下六条是实际用下来最有效的做法。

01
先给目标，别给步骤
说清最终要得到什么，而不是一步步指挥它怎么做。Agent 自己会规划路径，你只需在关键节点纠偏。指令越像需求文档，结果越接近预期。
02
一次性交代完整上下文
把背景、约束、格式要求、参考样例一起给。信息分批挤出来，是 Agent 跑偏的最大原因——省下的打字时间，会变成返工时间。
03
按任务切分，不要一锅炖
复杂任务拆成几个可以各自验收的阶段：先出大纲，再填内容，最后调格式。每步都确认，比一次性生成一大坨再整体返工高效得多。
04
让不同 Agent 各干擅长的
日常产出、文档、检索交给主力工具；深度重构、跨文件改动交给代码攻坚型；补全、解释类小问题用轻量工具。错配是最常见的效率损失。
05
把重复流程固化成模板
周报、日报、数据汇总这类周期性任务，做一次好用的指令就存下来复用，能做成定时任务的就别手动跑。第二次开始，成本应该接近于零。
06
交付前自己过一遍关键结论
Agent 写得快，但事实、数字和引用仍需你确认。把它当成一位效率极高的助理，而不是不会出错的权威——最终责任人始终是你。
一句话总结：把 Agent 当作需要明确交代任务的同事，而不是需要猜心思的搜索框。交代得越清楚、切割得越合理、复用得越充分，单位时间产出就越高。
